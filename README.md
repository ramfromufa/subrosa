# subrosa

Инструмент судного дня для передачи данных.
Проект выходного дня, а точнее вечера, родившийся из сиюминутной необходимости.

## Предыстория

Я использую OpenVPN на арендованном ВПС со времён блокировки Рутрекера для себя и близких. На сегодняшний день ещё и VLESS. Во время внепланового обслуживания сервера все конфигурации VLESS были сброшены, из-за чего «сообщники» потеряли доступ к заблокированному Телеграму.

В условиях отсутствия СМС на тарифном плане, нежелания держать ворох мессенджеров про запас и париться с email возникла задача передать новые конфиги пользователям, не диктуя длинную тарабарщину по телефону, избегая ада в духе «S как доллар».

## Функционал и устройство

Появилась идея накидать максимально простой одностраничный сайт. 

* Все передаваемые данные хранятся в коде страницы сайта в зашифрованном алгоритмом AES виде. Для каждого блока данных — свой ключ.
* При вводе ключа в форму на сайте JavaScript на стороне клиента хеширует его в короткую строку заданной длины SHA-256.
* По этой строке-указателю в массиве данных находится нужный зашифрованный блок и расшифровывается этим же ключом прямо в браузере.
* Для надёжности форма принимает только целое положительное число.

### Плюсы:

* Вся математика и алгоритмы выполняются в браузере клиента. Сервер отдаёт только статический сайт. Риск инъекций или серверных уязвимостей сведён к нулю.
* Минимальная нагрузка на железо для самых дешёвых ВПС.

### Минусы:

* Каждый клиент скачивает всю базу данных, благо, в зашифрованном виде. Инструмент предназначен для личного использования в малых масштабах.
* Сайт расшифровывает и выводит только последний добавленный блок данных для конкретного ключа. 
* Вероятно, к минусам стоит добавить наличие как минимум двух разных блоков данных, зашифрованных по одному ключу разными алгоритмами. 

В моём распоряжении были ВПС, доменное имя, безотказный ИИ от Гугла и отличная тема для беседы. Гугл выдал пару файлов проекта, инструкцию по настройке Nginx, упомянул Сертбота. Я развернул сайт и обзвонил банду. Объяснил ситуацию и велел всем ввести на сайте свой номер телефона. Прошу заметить, мне не пришлось надиктовывать ключ по телефону. Достаточно было использовать механику секретного вопроса для восстановления доступа к аккаунту. Позже я шлифанул `index.html` и `index.js`, поместил базу ответов в отдельный файл `data.js`, накидал скрипты автозапуска сайта и добавления новых ответов.

## Установка

```bash
sudo apt update                                  # Обновление пакетов
sudo apt install git                             # Установка git
git clone https://github.com/ramfromufa/subrosa  # Клонирование репозитория проекта
cd subrosa                                       # Переход в директорию проекта
chmod +x setup.sh                                # Разрешение файлу исполнять в рамках дозволенного
./setup.sh                                       # Запуск сайта
chmod +x add.sh                                  # Разрешение исполнять и быть исполняемым
./add.sh                                         # Добавление ответа
```

Разработано в соавторстве с Gemini AI и холодным нефильтрованным.
